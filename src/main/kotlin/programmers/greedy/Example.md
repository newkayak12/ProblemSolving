## 패턴 1. 정렬 + 선택

### 1-1. 회의실 배정
**문제 설명**
스타트업 X사는 공용 회의실이 하나뿐입니다. 여러 팀이 신청한 회의의 [시작, 종료] 시각이 주어질 때, 겹치지 않게 진행할 수 있는 최대 회의 수를 구하세요. 한 회의의 종료 시각과 다음 회의의 시작 시각이 같으면 겹치지 않는 것으로 봅니다.

**제한사항 (추정치)**
- 1 ≤ meetings.length ≤ 100,000
- 0 ≤ 시작 < 종료 ≤ 1,000,000,000

**함수 시그니처**
```kotlin
fun solution(meetings: Array<IntArray>): Int
```

**입출력 예**

| meetings | result |
|---|---|
| [[1,4],[2,3],[3,5],[0,6],[5,7],[3,9],[5,9],[6,10],[8,11],[8,12],[2,14],[12,16]] | 5 |

**입출력 예 설명**
종료 시각 기준 정렬 후 그리디로 선택 시 (2,3)→(3,5)→(5,7)→(8,11)→(12,16), 총 5개.

### 1-2. 보상 카드 (스탯 누적)
**문제 설명**
RPG 게임에서 캐릭터가 조건부 스탯 카드를 획득합니다. 카드마다 [필요 스탯, 보상값]이 있고, 현재 스탯이 필요 스탯 이상일 때만 카드를 사용해 보상값만큼 스탯을 올릴 수 있습니다. 카드는 필요 스탯 오름차순으로 한 번씩만 확인하며, 조건 미달 카드는 그냥 지나칩니다(재시도 없음). 모든 카드를 확인한 후 캐릭터의 최종 스탯을 구하세요.

**제한사항 (추정치)**
- 1 ≤ cards.length ≤ 100,000
- 0 ≤ 필요 스탯, 보상값, start ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(cards: Array<IntArray>, start: Int): Int
```

**입출력 예**

| cards | start | result |
|---|---|---|
| [[1,10],[3,3],[20,100],[2,5]] | 1 | 19 |

**입출력 예 설명**
필요 스탯 순 정렬: [1,10]→[2,5]→[3,3]→[20,100]. 1→11→16→19까지 진행 후 [20,100]은 조건 미달로 스킵. 최종 19.

### 1-3. 체육복
**문제 설명**
체육 수업을 앞두고 몇몇 학생이 체육복을 도난당했습니다. 여벌 체육복을 가진 학생은 바로 옆번호(앞 또는 뒤) 학생에게만 빌려줄 수 있고, 자신도 도난당했다면 남에게 빌려줄 여유가 없습니다(자기 것 우선). 체육수업에 참여할 수 있는 최대 학생 수를 구하세요.

**제한사항 (추정치)**
- 1 ≤ n ≤ 100,000
- lost, reserve는 1 이상 n 이하의 서로 다른 정수 배열

**함수 시그니처**
```kotlin
fun solution(n: Int, lost: IntArray, reserve: IntArray): Int
```

**입출력 예**

| n | lost | reserve | result |
|---|---|---|---|
| 5 | [3,4] | [2,5] | 5 |

**입출력 예 설명**
학생2(여벌)가 학생3에게, 학생5(여벌)가 학생4에게 빌려줘서 전원 수업 가능.

## 패턴 2. 우선순위 큐
### 2-1. 보상 카드 (마감일)

**문제 설명**
게임 이벤트에서 하루에 카드를 하나만 사용할 수 있습니다. 카드마다 [마감일, 보상값]이 있으며, 카드는 자신의 마감일 이전(포함) 어느 날짜에든 사용할 수 있습니다. 단, 하루에 카드 하나만 쓸 수 있으므로 같은 날짜를 두 카드가 동시에 쓸 수 없습니다. 사용할 카드와 사용 날짜를 자유롭게 선택할 수 있을 때, 얻을 수 있는 보상값의 최대 합을 구하세요. (모든 카드를 다 쓸 필요는 없습니다.)

**제한사항 (추정치)**
- 1 ≤ cards.length ≤ 100,000
- 1 ≤ 마감일 ≤ cards.length
- 0 ≤ 보상값 ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(cards: Array<IntArray>): Int
```

**입출력 예**

| cards | result |
|---|---|
| [[2,100],[1,19],[2,27],[1,25],[1,15]] | 127 |

**입출력 예 설명**
보상값 내림차순으로 하나씩 검토하며, 각 카드를 "자신의 마감일 이하이면서 아직 비어있는 날짜 중 가장 늦은 날짜"에 배정한다.

- [2,100]: 2일 사용 가능 → day2 배정 (누적 100)
- [2,27]: 2일은 이미 사용됨, 1일 사용 가능 → day1 배정 (누적 127)
- [1,25]: 1일도 2일도 이미 사용됨, 배정 불가
- [1,19], [1,15]: 마찬가지로 배정 불가

최종 합계 100+27=**127**

### 2-2. 허프만 코딩
**문제 설명**
메시지 압축 시스템을 설계합니다. 문자별 등장 빈도가 주어질 때, 매번 가장 작은 두 빈도를 합치며 그 값을 비용으로 누적합니다. 전체 인코딩에 드는 총 비용을 구하세요.

**제한사항 (추정치)**
- 2 ≤ freqs.length ≤ 100,000
- 1 ≤ freqs[i] ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(freqs: IntArray): Long
```

**입출력 예**

| freqs | result |
|---|---|
| [5,9,12,13,16,45] | 224 |

**입출력 예 설명**
5+9=14 → 12+13=25 → 14+16=30 → 25+30=55 → 45+55=100. 누적 14+25+30+55+100=224.

목재소에서 여러 막대를 하나로 이어 붙이려 합니다. 두 막대를 이을 때 드는 비용은 두 길이의 합이고, 이어 붙인 막대는 다시 다음 연결의 후보가 됩니다. 모든 막대를 하나로 합치는 데 드는 최소 총비용을 구하세요.

**제한사항 (추정치)**
- 2 ≤ sticks.length ≤ 100,000
- 1 ≤ sticks[i] ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(sticks: IntArray): Long
```

**입출력 예**

| sticks | result |

### 2-4. 작업 스케줄링 *(기존 2-5, 정답 오류 정정)*
**문제 설명**
공장에서 여러 작업을 처리하려 합니다. 작업마다 [소요시간, 마감일]이 있고, 한 번에 한 작업만 처리할 수 있습니다(동시 처리 불가). 선택한 작업들을 순서대로 처리했을 때 각 작업의 완료 시각(누적 소요시간)이 자신의 마감일을 넘지 않도록 하면서, 처리 가능한 최대 작업 수를 구하세요.

**제한사항 (추정치)**
- 1 ≤ jobs.length ≤ 100,000
- 1 ≤ 소요시간, 마감일 ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(jobs: Array<IntArray>): Int
```

**입출력 예**

| jobs | result |
|---|---|
| [[2,2],[1,1],[3,3],[1,2]] | 2 |

**입출력 예 설명**
(원본 정답 3은 오류. 전체 조합 완전탐색으로 재검증함)
[1,1]을 먼저 처리(완료 시각1, 마감1 충족) 후 [1,2]를 처리(완료 시각2, 마감2 충족) → 총 2개. 세 개 이상을 포함하는 모든 조합·순서는 마감을 위반함.

### 3-2. 분할 가능 배낭 (Fractional Knapsack)
**문제 설명**
도굴꾼이 배낭에 보물을 담으려 합니다. 이번 배낭은 특수해서 보물을 쪼개서 담을 수 있고, 쪼갠 비율만큼 가치도 비례해서 얻습니다. 아이템별 [무게, 가치]와 배낭 용량이 주어질 때, 담을 수 있는 최대 가치를 구하세요.

**제한사항 (추정치)**
- 1 ≤ items.length ≤ 100,000
- 1 ≤ 무게, 가치 ≤ 1,000,000
- 1 ≤ capacity ≤ 1,000,000

**함수 시그니처**
```kotlin
fun solution(items: Array<IntArray>, capacity: Int): Double
```

**입출력 예**

| items | capacity | result |
|---|---|---|
| [[10,60],[20,100],[30,120]] | 50 | 240.0 |

**입출력 예 설명**
무게당 가치 순: [10,60](6.0)→[20,100](5.0)→[30,120](4.0). 앞 두 개 전부 담고(30kg, 160) 남은 20kg로 세 번째를 2/3만큼 담아 80 추가 → 240.0.

### 3-3. 최소 주유 횟수
**문제 설명**
장거리 배송 트럭이 목적지까지 주유 없이 갈 수 없어, 중간 주유소에서 최소 횟수로 주유하며 이동하려 합니다. 주유소별 [출발점으로부터의 위치, 채울 수 있는 연료량], 시작 연료, 목적지까지 거리가 주어질 때(연료가 0 미만이 되면 도달 실패), 목적지 도달에 필요한 최소 주유 횟수를 구하세요. 도달이 불가능하면 -1을 반환하세요.

**제한사항 (추정치)**
- 0 ≤ stations.length ≤ 100,000
- 0 ≤ 위치 < dist ≤ 1,000,000,000
- 0 ≤ start_fuel, 주유 가능량 ≤ 1,000,000,000

**함수 시그니처**
```kotlin
fun solution(stations: Array<IntArray>, startFuel: Int, dist: Int): Int
```

**입출력 예**

| stations | start_fuel | dist | result |
|---|---|---|---|
| [[10,60],[20,30],[30,30],[60,40]] | 40 | 100 | 1 |

**입출력 예 설명**
시작 연료로 위치40까지 도달 가능한 구간 내 주유소(10,20,30) 후보를 확보한 뒤, 그중 최대 주유량(60)을 한 번 사용하면 연료 100으로 목적지 도달. 주유 1회.

## 패턴 4. 정렬 기반 순서 결정

```kotlin
fun solution(activities: Array<IntArray>): Int
```

회사 전체 회의 일정이 주어졌을 때, 모든 회의를 동시에 진행 가능하게 하려면 최소 몇 개의 회의실이 필요한지 구하려 합니다. 회의별 [시작, 종료] 시각이 주어질 때 필요한 최소 회의실 수를 구하세요.

**제한사항 (추정치)**
- 1 ≤ meetings.length ≤ 100,000
- 0 ≤ 시작 < 종료 ≤ 1,000,000,000

**함수 시그니처**
```kotlin
fun solution(meetings: Array<IntArray>): Int
```

**입출력 예**

| meetings | result |
|---|---|

**입출력 예 설명**
0~30 회의가 진행되는 동안 5~10, 15~20이 겹치는 시점이 있어 최소 2개 회의실 필요.

### 4-3. 정렬 기준 비교 (반례 확인)
**문제 설명**
위 4-1과 같은 세션룸 상황에서, 이번엔 정렬 기준에 따라 결과가 어떻게 달라지는지 직접 비교해보려 합니다. 활동별 [시작, 종료]가 주어질 때(한 자원만 사용), 종료 시각 기준 정렬로 그리디를 적용한 결과와 시작 시각 기준 정렬로 적용한 결과를 각각 구하세요.

**제한사항 (추정치)**
- 1 ≤ activities.length ≤ 100,000
- 0 ≤ 시작 < 종료 ≤ 1,000,000,000

**함수 시그니처**
```kotlin
fun solution(activities: Array<IntArray>): Pair<Int, Int> // (종료 기준 개수, 시작 기준 개수)
```

**입출력 예**

| activities | result |
|---|---|
| [[1,10],[2,3],[4,5]] | (2, 1) |

**입출력 예 설명**
종료 기준: (2,3)→(4,5) 선택 가능, 2개. 시작 기준: (1,10)을 먼저 선택하면 이후 전부 겹쳐 1개뿐. 어느 기준이 올바른 그리디인지 직접 판단해볼 것.

## 패턴 판별 힌트

| 패턴 | 신호 |
|---|---|
| 정렬 + 선택 | 한 번 정렬 후 순차 판단만으로 충분 |
| 우선순위 큐 | "지금까지 본 것 중 최소/최대"를 계속 갱신 |
| 단일 경로 탐색 | 각 선택이 독립적, 분할 가능하거나 배수 조건 성립 |
| 정렬 기반 순서 결정 | 정렬 기준 자체가 정답을 결정 |
